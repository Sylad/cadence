# Changelog

What each release of cadence brings to the people who use it. Format:
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); newest first, one
section per git tag. `(L12)` cites the lot of the plan (`.cadence/raf.yaml`, `docs/plan/raf.yaml` before L246)
that brought the change.

Versions 0.1 to 0.4 were never tagged nor published (0.3.0 and 0.4.0 never
reached npm): what they brought is part of the first tagged release, 0.5.0.

## [Unreleased]

### Fixed

- `raf migrate` (L284, `docs/raf.md`): a path built with pathlib's `/` operator (`Path(...) / "docs" / "plan"`) and a text file that is not UTF-8 are now readers not handled (the command refuses instead of leaving the first on the old place or corrupting the second); `docs/perf/ventilation.py` reads the plan at `.cadence/raf.yaml`, then `docs/plan/raf.yaml`, so a replay counts cadence's own lots again.
- `raf migrate` (L305): a file over 2 MiB that cites `docs/plan` is a reader not handled (it used to be skipped without a word); a refusal without `--dry-run` no longer prints « lecteurs mis à jour » before refusing.
- `raf migrate` (L305): a file over 2 MiB is searched for the path by blocks of bytes, never read whole nor decoded into a string (a tracked 600 MiB GeoTIFF used to crash the command with `ERR_STRING_TOO_LONG` and a raw trace).
- `raf migrate` (L284): a `join(` split over several lines and `Path("docs") / "plan"` are readers not handled too (the command used to move the plan and leave them reading `docs/plan/raf.yaml`).
- cadence's own migration (L284): `docs/fonctionnement.md` and `docs/stabilite.md`, shipped to npm, name the legacy `docs/plan/raf.yaml` again (the migration had rewritten it into « the legacy `.cadence/raf.yaml` »); they and `test/ventilation-plan.test.ts` (the fallback test) are under `migrate.keep`, so replaying `raf migrate` in cadence finds nothing to do.
- `cadence orchestrate` worktree mode (experimental, not enabled; L304, `docs/orchestrate.md`): the recovery of a kept branch by a new wave (L301) reports a failing `git worktree move` / `git branch -m` in the journal (`non reprise : déplacement ou renommage de la branche refusé par git (…)`, the move undone) instead of silently starting the lot afresh; the documentation gives the branch name of a wave started at the root (`cadence/<wave>/_--<lot>`) and the manual integration procedure, and tests cover a lot handed back at the integration step and a new wave without `CADENCE_EXPERIMENTAL_WORKTREES`. `[Unreleased]` holds a single `### Fixed`, `### Added` and `### Changed` again.
- `cadence orchestrate` (L303, `docs/orchestrate.md`): the report of a write step cut at its time limit also counts the commits and the uncommitted files left in the neighbouring repositories (`repos:`), prefixed with their name; a cut that left work only there hands the lot back instead of failing.
- `cadence orchestrate` worktree mode (experimental, not enabled; L303, `docs/orchestrate.md`): a lot handed back after the short review of the rebased diff and resumed with `--resume --integrate` no longer writes that review's verdict twice in its plan verdict; a lot resumed at the integration whose branch still exists but lost its `branch.<name>.cadence-base` key is no longer reported as « commits abandonnés » (removed branch).
- `cadence orchestrate` worktree mode (experimental, not enabled; L299, `docs/orchestrate.md`): the lead's branch and tree are checked again right before the fast-forward and before the plan is written, so a lead moved to another branch (or with a modified tracked file) during the replayed checks or the short review receives neither the fast-forward nor a plan commit, and the lot is handed back with `next: integrate`.
- `cadence orchestrate` worktree mode (experimental, not enabled; L301, `docs/orchestrate.md`): a lot handed back outside the integration step (non-compliant review, red tests, moved `HEAD`, touched plan, acceptance lock) has a recovery path — a new wave of the same lot recovers its most recent branch `cadence/<wave>/<lot>` and plays on from its commits (the docs also give the by-hand integration), unless its worktree holds a modified tracked file or one of its commits touches the plan; the integration of a lot with a UX review now runs after the application is stopped; a wave launched from the repository's root puts its worktrees outside the repository (and no longer fails on the branch name `cadence/<wave>/.--<lot>`); `git`/`tryGit` and the plan-owned-file test are shared; `waveReadsIntegrate`/`waveReadsReplay` are tested.
- `cadence orchestrate` worktree mode (experimental, not enabled; L300, `docs/orchestrate.md`): a lot resumed with `--resume --integrate` whose branch `cadence/<wave>/<lot>` no longer exists (removed by `--remove-worktree --abandon-commits`) gets no worktree recreated at the repository's top and is handed back as « commits abandonnés » with `next: integrate`, even when several lots of the group are resumed together; a verdict is never written against a null `commit`.
- Sourcing a sheet rule after `--answer` (L302, `docs/orchestrate.md`) edits only the `statut`, `source` and `si_faux` lines of the rule: the 17 sheets of `docs/specs` keep `[R2]` (it became `[ R2 ]`), their comments and their folded lines. An answer that deletes or changes the rule (« non, supprime R3 », « change en X ») no longer marks it `sourcee` as it stands: it is left to the resumed `spec` session, or goes back to the lead when the session does not handle it.
- `cadence orchestrate --resume --answer` on an expensive-to-undo hypothesis of the sheet (L297, `docs/orchestrate.md`): the program itself sets the rule to `sourcee` (`source: réponse du lead, <date>, vague <id>`) and commits the sheet before the resumed `spec` session, so a lost or silent session no longer hands the lot back as « fiche non conforme » (L279, R27).
- `cadence orchestrate` test gate (L291, `docs/orchestrate.md`): files deleted by the lot no longer count as code without a test (a lot removing dead code triggered a ≈ 65 k-token pass), the neighbour repositories of the lot (`repos:`) are read like the main one, and the docs say that on a light lot the gate leads to an Opus review.

### Added

- `raf migrate [--dry-run]` (L284, `docs/raf.md`): moves `docs/plan/raf.yaml` to `.cadence/raf.yaml` (`git mv`) and rewrites the readers of the old path in the repository (scripts, tests, CI, skills, documentation; the history — `CHANGELOG*`, `*.ndjson`, `.cadence/` — is left alone). `--dry-run` lists the move and every file touched; the command refuses, changing nothing, while a reader is not handled (`file:line` listed: another file of `docs/plan/`, a path built piece by piece, a binary) unless `migrate.keep` of `cadence.yaml` declares it; it can be run again and refuses when both plans exist or none does.
- `cadence orchestrate`: the time limit of a write step is proportioned to the lot (L298) — `timeouts.implement` (45 min) is the base for 0.25 day, doubled for 0.5 day, 1.5 times more for a lot with a sheet, 4 times at most — and extended by 15 minutes (8 times at most) at each deadline where the session committed since the previous one. A step cut at its deadline reports in the table the commits kept and the work left uncommitted (files, tests, lines) and hands the lot back to the lead, instead of a bare « délai dépassé » failure. Seen on 24-10: L279's implementation (0.5 day with a sheet) was cut at 45 min after 6 commits, 44 green lines uncommitted.
- `cadence orchestrate`: one git worktree per lot (L279, `docs/orchestrate.md`, `docs/lead.md`) — **experimental, not enabled**: `orchestrate.worktrees: true` is refused (exit 2, also with `--dry-run`) unless `CADENCE_EXPERIMENTAL_WORKTREES=1` is set, until lots L299, L300 and L301 (defects found by two code reviews) are done; the default mode is unchanged. With `orchestrate.worktrees: true` in `cadence.yaml` (default `false`: nothing changes), independent lots of one repository play at the same time within `--max-sessions`, each on its own branch `cadence/<wave>/<project>--<lot>` in its own worktree (created when the lot takes its place, after its `raf start`; a lot that declares `repos:`, a detached `HEAD` or a lone lot stays in the repository). The plan is never written in a worktree: `raf start`, notes, sub-task closing and the review verdict are written by the program in the project's checkout, one at a time under an integration lock (bounded wait of 10 minutes), after checking the repository is still on its start branch with no modified tracked file. A lot is integrated **before** it is `ready`: rebase on the repository's branch (a conflict is aborted and handed back, never resolved by a session), tests and build re-run when the rebase changed the commits, verdict carried over to the integrated sha with a `reporte: { de, vers, patchId }` trace when the patch-id of the diff is unchanged, a short `review-small` of the rebased diff otherwise, then `merge --ff-only` and a plan-only commit; the `raf done` gate is unchanged.
