### Fixed

- The gate no longer gives misleading reds on a stale environment (L764, [docs/deliver.md](docs/deliver.md#verify---gate-replay-the-projects-gate-at-a-sha-l348)): before playing, `cadence verify --gate` and the gate of a `cadence run` read `scripts/environnement-porte.mjs` in the folder where they will play — (a) a `node_modules` whose `.package-lock.json` differs from `package-lock.json` (package, installed and expected versions), (b) a Node on the gate's `PATH` that does not satisfy `.nvmrc`, `.node-version` or `engines.node`. Stale, nothing is played: exit 2 for `verify --gate` (not a verdict), state `environnement-perime` for a run (no correction asked from the session), each problem with its fix command (`cd <dir> && npm ci`, `nvm install …` then restart the session whose `PATH` the gate inherits). `CADENCE_PORTE_ENV=jouer` plays anyway. Five such reds on 17-11.
- The gate of a `cadence run` reads `orchestrate.test` / `orchestrate.build` from the run's own `cadence.yaml` (after the rebase, and again after a correction), not from the main repository: a run that fixes its own gate command is judged by it; when the commands differ from the main tree's, the run's output says so (L764, [docs/v2/2026-11-09-cadence-run.md](docs/v2/2026-11-09-cadence-run.md)).
