- `cadence run --fond` survives the Claude Code session that launched it (L709, issue #55 of the pro account, D-7, [docs/v2/2026-11-09-cadence-run.md](docs/v2/2026-11-09-cadence-run.md)): on 11-11 two runs stopped the minute their launching session closed (2 runs lost, 3 h of slot). The run's `claude` sessions no longer inherit what binds a command to the Claude Code session that ran it (`CLAUDE_PID`, `CLAUDE_SSH_*`, `CLAUDE_CODE_CHILD_SESSION`, `CLAUDE_CODE_MESSAGING_*`, `CLAUDE_CODE_SDK_HAS_HOST_AUTH_REFRESH`, `CLAUDE_CODE_HOST_SESSION_ID`, `CLAUDE_CODE_SESSION_ID`), and the detached relaunch keeps Node's options. `--liste` shows `interrompu` (with the resume command) for an `en-cours` run whose process is dead; the state on disk is unchanged. The session id is written in the run state at launch (`claude --session-id`), so `cadence run --reponse <id>` resumes a run that died during its first session, same session, same worktree. `v2/test/run-fond-l709.test.ts` kills the whole process group of the launching shell and checks the run and its session live on and reach integration.
