### Fixed

- One `cadence.yaml` now serves both `cadence ref` and `cadence run` (L760): the key `references:` had two incompatible readers, `cadence ref` wanting an object `{ dir }` and `cadence run` a list of `{ mots, docs }`, so a project could not use both (seen on 16-11). The single documented form is `references: { dir, run: [{ mots, docs }] }` ([docs/config.md](docs/config.md#references-cadence-ref-and-cadence-run)), read by the same code (`scripts/references.mjs`) in both commands and in the gate that validates `cadence.yaml`. The former list form of `cadence run` is still read as `references.run`, with a migration line from each command, never ignored; a malformed key (unknown key, empty `mots` or `docs`, a non-text word) is refused by all three with the key at fault, and `cadence run` refuses it before creating its worktree.
- The wrapper of a `cadence run` session no longer dies when a signal reaches it right after launch (L760, red full gate): its traps were set after the session was started in the background, so a SIGTERM in that window killed the wrapper and the run wrote « l'enveloppe … a été tuée par SIGTERM » instead of the session's real signal (4 of 300 launches under CPU contention, 0 of 300 now). The traps are set first and read `$!`.
