### Fixed

- `cadence run --liste` no longer shows a run as `conflit` (or `refus-integration`, `porte-rouge`…) once the lead has merged it by hand: it shows `integre a la main` when the head of the run's branch is an ancestor of the target branch. Any other case keeps the run's state, followed by a line `commits absents de la cible : N`. `--liste` only displays: a cherry-pick, a squash or a conflict resolved by hand is never recognized (L745, issue #62, [docs/v2/2026-11-09-cadence-run.md](docs/v2/2026-11-09-cadence-run.md)).
- `cadence run --reponse` refuses a run closed by `--clore` instead of starting a session on its removed branch and rewriting its state to `echec` (L745 review).

### Added

- `cadence run --clore <id>` closes a finished run, merged or not, without losing anything. It first archives every known head of the run under `refs/cadence/archive/` (the head of its branch, the HEAD of its worktree, detached or hand-deleted included, and the head saved at the end of the run), checks that each archive exists, then removes the branch. The worktree folder is removed only when it is clean (no modified or untracked file, submodules included, no initialized submodule); otherwise it stays and the command says why. It refuses a run that can still be resumed, and refuses without touching anything when an archive cannot be written (L745 fifth pass).
- `cadence run --archives` lists the archives and, under each one, the git command that turns it back into a branch (L745 fifth pass).

### Removed

- `cadence run --clore <id> --force`: nothing is lost by `--clore` any more, so there is nothing to force. The recognition of a replayed commit by patch-id and the ten-row decision table are removed with it; four reviews in a row had each found a case where that proof was wrong and `--clore` deleted the only copy of some work (L745 fifth pass).
