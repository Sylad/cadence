### Changed

- A `cadence run` holds only the files it touches, no longer the whole branch (L796, issue #70, [docs/v2/2026-11-09-cadence-run.md](docs/v2/2026-11-09-cadence-run.md)): the pre-commit hook lets the lead commit on the starting branch when the commit's files are disjoint from what the run's worktree changes (committed or not, untracked included), and refuses only a commit that touches one of them, naming the files. A gate played in the main tree still holds the whole branch; `raf` writes still go to the pending plan (L779 unchanged).
- When the starting branch moved during the gate with commits on files the run does not touch (and not `cadence.yaml`), the run rebases and integrates by fast-forward without replaying the gate, instead of replaying it up to three times and ending `refus-integration`; the end line says so: the integrated sha has no gate verdict, and the pre-push hook requires `cadence verify --gate` at that sha (L786). An overlap keeps the L723 path (gate replayed, conflict handed to the session, `conflit` as before).

### Fixed

- A `raf start <lot>` left uncommitted before `cadence run --lot <lot>` is committed by the run at launch (`plan: <lot> démarré`, or the project's `plan.commit` template) when the plan differs from HEAD only by that lot's start: the lot can no longer end `refus-integration` because of its own start (L796, about 50 min lost once). A plan with other changes is left as is, with the usual warning.
