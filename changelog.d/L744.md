### Fixed

- The `livreur` agent no longer stops on a brief without `lead.ux` (« brief incomplet : valeur de lead.ux absente »): an absent value is `human`, the default documented in [docs/lead.md](docs/lead.md), and it only matters for a visible lot. It now reads the `deliver` key of `cadence.yaml` before any command: in a repository without it, nothing is deployed, so it pushes the sha then the plan commit (by its own sha, only when it sits right on the sha), never runs `cadence deliver` (whose `--dry-run` failed with code 2 after `raf done`, leaving the plan commit unpushed), asks for no base URL and no QA, and says it in one line (`L84 poussé 3d6edf4 avec le commit du plan 9a1b2c3, rien à déployer (pas de clé deliver)`) (L744, [agents/livreur.md](agents/livreur.md)).
- The `livreur-delegue` sheet (docs/specs/livreur-delegue/fiche.yaml), [docs/skills.md](docs/skills.md) and the `lead` skill now describe that behaviour too: R14 no longer counts an absent `lead.ux` as « brief incomplet », R10 and R3 push the plan commit by its own sha and skip `cadence deliver` without a `deliver` key, and the contract carries the `… poussé …, rien à déployer (pas de clé deliver)` line (L744, review r1).
