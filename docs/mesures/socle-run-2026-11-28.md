# Le socle d'une session de `cadence run`, allégé (L936, D-45 piste 1)

Le bilan d'usage du 27-11 (7 jours, 348 runs) donnait **~71 k jetons** au premier appel d'un run (médiane, minimum 64 k), soit ~21 % du
coût des runs en relecture du cache. L705 avait coupé plugins, connecteurs claude.ai et mémoire ([mesure du 12-11](socle-session-2026-11-11.md)) ;
depuis, le `CLAUDE.md` du dossier parent et les outils intégrés de Claude Code ont grossi. L936 coupe ce dont une session `claude -p` de run
n'a pas besoin, sans toucher aux briefs du banc. Cible : premier appel sous 35 k.

## Méthode

Vraies sessions `claude -p`, Claude Code 2.1.325, le 28-11, lancées comme `session()` de `cadence run` en mode léger : `argsClaude` et
`reglagesRun` compilés (`v2/dist`), le hook `cadence-permise` du run, les `--disallowedTools` du run, l'environnement du run (variables de la
session lanceuse retirées, `KUBECONFIG=/dev/null`), dans le worktree d'un vrai run (sous `~/projects/developpeur/.cadence-run/`, donc sous le
`CLAUDE.md` parent). Prompt : le brief gagnant `bras-A.md` rendu avec une demande neutre (« réponds seulement ok »), `--max-turns 1`.
Premier appel = `input + cache_creation + cache_read` du premier message `assistant`. Modèle Opus 5.5 (celui des runs), chaque ligne deux fois
pour avant et après. « Avant » : le code de L705 (les clés de L936 retirées des réglages, outils du lead permis).

## Le socle, poste par poste

Chaque coupe seule, sur le socle d'avant (70 115) ; la somme (45 354) colle à l'écart mesuré ensemble (45 189).

| poste | coupé par | jetons |
|---|---|---:|
| outils intégrés du lead (`Artifact`, `Workflow`, `ScheduleWakeup`, `Cron*`, `SendMessage`, `Suggest*`, `Search*`, `Monitor`…, 24) | `--disallowedTools` (`OUTILS_DU_LEAD`) | 20 703 |
| `CLAUDE.md` du dossier parent du dépôt (consignes du lead) | `claudeMdExcludes` | 14 233 |
| agents de l'utilisateur (`<config>/agents`, 16) | `permissions.deny` `Agent(<nom>)` | 4 877 |
| `CLAUDE.md` de l'utilisateur (`<config>/CLAUDE.md`) | **gardé** (`userClaudeMd: false` le coupe) | 3 624 |
| agents du plugin cadence (11 : relecteurs, rédacteurs de fiches, livreur…) | `permissions.deny` | 2 577 |
| skills de l'utilisateur non cités (36 sur 39) | `skillOverrides: off` | 2 559 |
| serveurs MCP de l'utilisateur (`.claude.json`, 2) | `deniedMcpServers` | 405 |

Reste ~24,9 k : le prompt système et les schémas des outils gardés (Bash, Read, Edit, Write, Agent, Skill, ToolSearch, WebSearch,
NotebookEdit, noms des outils différés de playwright), le `CLAUDE.md` de l'utilisateur et celui du dépôt, le brief, les skills intégrés et ceux
du compte, les skills du plugin cadence et les agents intégrés.

## Ce qui reste, et pourquoi

- **Gardés** : hooks de garde (`premier-plan`, `cadence-permise`, lecture obligatoire du mode complet), `CLAUDE.md` du dépôt et de
  l'utilisateur, plugins cadence et playwright, agents intégrés (`Explore`, `general-purpose`, `Plan`, `web-fetch`…) et ceux du projet
  (`.claude/agents`), skills du projet, intégrés, et de l'utilisateur quand la demande, le brief ou un `CLAUDE.md` gardé les nomment
  (`interface-utilisable`, que cite le `CLAUDE.md` de l'utilisateur), serveurs MCP du projet et des plugins.
- **Skills du plugin cadence** (~1 k) : `skillOverrides` ne les coupe pas (trois formes essayées le 28-11 : `lead`, `cadence:lead`,
  `cadence@cadence:lead` ; la liste les garde) ; couper le plugin retirerait aussi ses agents et son hook. Laissés.
- **`disableBundledSkills`** a *ajouté* 3,5 k au premier appel (mesuré) : non retenu.
- **`--strict-mcp-config`** retire aussi le serveur de playwright : non retenu, `deniedMcpServers` vise les seuls serveurs de l'utilisateur.

Tout se lit sur la machine (dossier de configuration de Claude Code, `installed_plugins.json`, `.claude.json`) et dans `run.session` du
`cadence.yaml` du dépôt ([config](../config.md#session-base-of-a-run-runsession)) : aucun chemin ni nom propre à un poste dans le code.

## Coût

Avec la grille de [`cadence cost`](../cost.md) (Opus 5.5 : cache écrit 8 $/M, lu 0,20 $/M) et le déroulé médian d'un run (37 appels,
[mesure du 11-11](socle-session-2026-11-11.md#coupes-proposées-chiffrées-avec-cadence-cost)) : 45 k jetons en moins écrits une fois (0,36 $)
et relus à 36 appels (0,33 $), **~0,69 $ par session de run**, de l'ordre de 240 $ sur les 348 runs de la semaine du 27-11. Estimation
linéaire, non mesurée sur une facture.

## Limites

- Premier appel seulement ; les appels suivants relisent le même socle du cache, non mesurés au-delà.
- Réussite et durée non mesurées : le banc ne prend pas les coupes du run (décision de L705, inchangée), son bras `cadence run` reste sans
  elles. Qu'aucun run n'ait besoin d'un outil, agent ou skill coupé est à suivre sur les runs réels (un refus `Agent(…)` ou un outil absent
  dans le journal).
- Un skill de l'utilisateur gardé parce que son nom est un mot de la demande (« local », « save ») : faux positif sans danger.
