### Fixed

- `cadence run` keeps the report its session gave when it finished its work (issue #57 of the pro account, [docs/v2/2026-11-09-cadence-run.md](docs/v2/2026-11-09-cadence-run.md)): a task notification that arrived after that report (a background agent or command finishing late) opened one more turn, and its reply replaced the report in the run's state and in the `fond-<id>.log` journal, so the commits, the sealed tests to reseal and the verified / not verified lines were only left in the session transcript. Sessions now talk `--output-format stream-json` and turns are counted on its `result` events: the report is the last message of the turn opened by the prompt, whatever the notification looks like (in a real stream it is a `system/task_notification` event) and even when the late reply says « fini ». Every message is kept with its turn in the state (`messages`) and written to the journal in order; a later turn no longer decides the run's state (its error, exit code or quota text), only the cost and tokens come from the last `result`. The messages are kept whatever the session's end: finished work, but also a failure (`error_max_turns`, an API error), the 4 h deadline, a signal or a quota, which is exactly where the lead needs to read what was done and what remains; in those ends the state gets no `rapport` and the journal names the last message as the last one said before the stop. The failure detail names the error and quotes it (`session <id> : error_max_turns, code 1`), never « success ». Tests: `v2/test/run-rapport-57.test.ts`, on two captured streams and one full run per kind of end.
