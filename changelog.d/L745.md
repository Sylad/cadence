### Fixed

- `cadence run --liste` no longer shows a run as `conflit` (or `refus-integration`, `porte-rouge`…) once all its commits are on the target branch, merged or replayed by hand: it shows `integre a la main`, checked with `git cherry` against the run's branch, or against its head saved in the run state when the branch is gone. The new `cadence run --clore <id>` then removes the run's worktree and branch and marks it closed in its state; it refuses, saying why, while a commit of the run is missing from the target, while the run can still be resumed, or when its worktree has uncommitted changes (L745, issue #62, [docs/v2/2026-11-09-cadence-run.md](docs/v2/2026-11-09-cadence-run.md)).
