# Dossier de publication 2.0.6

Empreinte de v2 : 2b220bd21ebf

Décision de Sylvain, le 2026-11-13 : publier la 2.0.6 sur un dossier de décision, comme les 2.0.4 et 2.0.5. La garde exige un banc court et une séquence verts, joués avec juges (cadence run contre A) : ils n'ont pas été joués pour cette version. Ce qu'elle apporte supprime des pertes de temps vécues le jour même (runs refusés à l'intégration, écritures du lead pendant qu'un programme tient le dépôt, faux signal de livraison).

La garde accepte ce dossier parce qu'il cite l'empreinte exacte de la version publiée (`src/release.ts`, `gardeBancV2`). Le banc mécanique ci-dessous a mesuré cette même empreinte, sur le dépôt publié (`cadence`, branche `main`, 268a3a06).

## Ce qui est publié

Les lots terminés depuis le tag v2.0.5 (le détail est dans le CHANGELOG, assemblé depuis `changelog.d/`) :
- **L718** : `cadence deliver --constat [<sha>]` inscrit une livraison faite hors de `cadence deliver`, sans rien déployer, et la clé `deliver.deployed` dit quel sha est réellement déployé ; le tour ne compte plus comme non livrés des lots déjà en production.
- **L722** : `raf review`, `raf ux` et les écritures du registre des demandes sont mis en attente quand un programme tient le dépôt ; une revue mise en attente fige le commit qu'elle a relu ; un run ou une porte qui démarre nomme les fichiers non commités de l'arbre principal.
- **L723** : `cadence run` se rebase seul quand la branche cible a avancé pendant le run ; un conflit est résolu par la même session, la porte est rejouée sur le résultat rebasé, et le conflit est gardé dans l'état et le journal sans remplacer le rapport de travail.
- **L724** : la correction après une porte rouge est gardée dans l'état et le journal, et le rapport de travail reste intact, quota compris.
- **L725** : `raf review` ou `raf ux` sans verdict est refusé avant la mise en attente.
