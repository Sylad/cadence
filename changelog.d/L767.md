### Added

- `cadence run --purger [--dry-run]` empties `../.cadence-run/` of the runs of the current repository that were integrated or closed more than `run.purgeAfterDays` days ago (`cadence.yaml`, 14 by default) and whose worktree is gone: state, lock, captures, question, settings, and the `--fond` journal once no kept run cites it. A run in progress, waiting for an answer, in quota or handed back to the lead is never touched; a finished run whose worktree is kept is named. `--dry-run` lists without removing (L767, [docs/v2/2026-11-09-cadence-run.md](docs/v2/2026-11-09-cadence-run.md)).

### Fixed

- `cadence run --liste` now says when an interrupted, waiting or quota run with no live process has its head on the target branch (integrated by hand), with the `--clore` command, and `--clore` accepts it instead of refusing a run that "can be resumed" (L767).
