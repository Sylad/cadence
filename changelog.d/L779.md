### Fixed

- `raf start` on a branch held by a `cadence run` (or a gate in the main tree) goes to the pending plan like `raf note`, instead of writing `.cadence/raf.yaml` in the main tree (L779, issue #66, [docs/raf.md](docs/raf.md#a-branch-held-by-a-program-the-pending-plan-l695)). The documented launch `raf start <lot> && cadence run … --fond` no longer dirties the plan when another run holds the repository, and the next run no longer warns about an uncommitted `.cadence/raf.yaml`; the run that releases the branch applies the start. An invalid start (unknown lot, lot already started or closed, start of the same lot already pending) is refused at once. While queued (or while a live `cadence run --lot` serves it), the lot counts as in progress for the tour, `raf now`, `cadence session start`, the free-resources line and the draw of a wave: not drawable, its `uses:` held. Applied after the lot was started another way or closed, a queued start is dropped with a message instead of blocking the writes after it.
