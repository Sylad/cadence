### Fixed

- `cadence run --liste` no longer shows a run as `conflit` (or `refus-integration`, `porte-rouge`…) once all its commits are on the target branch, merged or replayed by hand: it shows `integre a la main`. The new `cadence run --clore <id>` then removes the run's worktree and branch and marks it closed in its state; it refuses, saying why, while a commit of the run is missing from the target, while the run can still be resumed, or when its worktree has uncommitted changes (L745, issue #62, [docs/v2/2026-11-09-cadence-run.md](docs/v2/2026-11-09-cadence-run.md)).
- `cadence run --liste` and `--clore` now follow one explicit rule, written as a table in the doc with one tested function per row, instead of heuristics. A run is `integre a la main` only when every commit reachable from its branch, from the HEAD of its worktree (detached included) and from the head saved at the end of the run is an ancestor of the target or has the same patch-id as a commit of the target; merge commits are included and never have a patch-id. A failing git command, a modified or untracked file in the worktree, or any other case means not integrated, and `--clore` refuses and names the reason. Submodules are never ignored (`diff.ignoreSubmodules`, `ignore = all` in `.gitmodules`), and `git cherry` is no longer used. Before, `--clore` could delete a submodule bump, commits made on a detached HEAD, uncommitted changes when `git status` failed, and the content of a merge commit (L745 fourth pass).

### Changed

- `cadence run --liste` and `--clore` no longer recognize a conflict resolved by hand from the content of the run's files: the patch-id differs, so the run stays `conflit`. `cadence run --clore <id> --force` is the only way to close a run that is not integrated; it now prints each commit that is lost (short sha and subject) and the heads of the run, and shows as `clos … par --force` in `--liste`. It still refuses a run that can be resumed, a worktree with uncommitted changes and a failing git command (L745 fourth pass).
- `cadence run --reponse` refuses a run closed by `--clore` instead of starting a session on its removed worktree and rewriting its state to `echec` (L745 review).
