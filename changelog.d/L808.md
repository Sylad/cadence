### Fixed

- Bench sequences (L808, [docs/etudes/banc-b68-court-2026-11-22.md](docs/etudes/banc-b68-court-2026-11-22.md)): the candidate arm's hook now refuses any call (`Bash`, `Read`, `Glob`, `Grep`) that cites a path the leak detector would count as a certain leak, with the same rule, now shared in `v2/hooks/lecture.mjs`. On 22-11 a Playwright probe placed in `qa/` did not find the package and the arm looked for it in `~/projects/developpeur`, which made the sequence red. The guard `CADENCE_LECTURE_BORNEE` is set by the bench only, never by `cadence run`. Only what a call reads is judged, by the hook and by the leak detector alike: the path fields of a tool (`file_path`, `path`, `notebook_path`, a `Glob` pattern) and the `Bash` command without its written texts (heredoc body not fed to an interpreter, `git commit -m` message, quoted `echo`/`printf` arguments unless their pipeline goes through `xargs`, `grep`/`rg` pattern; `rg --files <dir>` has no pattern, so the directory it lists is judged). A `Write` or `Edit` inside the clone whose content cites `~/projects`, or a `Grep` pattern that cites a path, is neither refused nor counted. In a sequence the hook also applies the rules of the step (`CADENCE_LECTURE_ZONES`: the rest of `sequences/` and the other arm's measures are refused), and `cadence run` drops both variables from the environment it inherits.
