### Fixed

- Running `cadence run` runs take a session slot (L710, issue #55 of the pro account, D-7, [docs/concepts.md](docs/concepts.md#slots-and-holds)): on 12-11 `cadence lead tour` printed `créneaux libres : 3 sur 3` while two runs were alive. A run registers in `$CADENCE_HOME/runs/` for its session, gate and integration and counts while it is `en-cours` with a live process on its lock (the `interrompu` check of `--liste`, L709); a dead or finished run counts for nothing. `cadence lead tour`, `cadence orchestrate --status` and the `cadence-hud` band add it to the sessions in progress and name it (`runs cadence run : 1 (projet <id>)`), and waves wait for its slot like a lead hold. `test/creneaux-runs-l710.test.ts` plays a live fake run (counted) and a dead pid (not counted) on both sides of the formula. A run is never held: `cadence lead hold` refuses (exit 2, nothing registered) a label that names the lot or the id of a live run, which would count it twice (a run plus `lead hold run-L710` read `1 sur 3` instead of `2 sur 3`), and the `lead` skill and [docs/lead.md](docs/lead.md#lead-hold-and-release) say so (`test/lead-hold-run-l710.test.ts`).
