[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); newest first, one
section per git tag. `(L12)` cites the lot of the plan (`.cadence/raf.yaml`, `docs/plan/raf.yaml` before L246)
that brought the change.

Versions 0.1 to 0.4 were never tagged nor published (0.3.0 and 0.4.0 never
reached npm): what they brought is part of the first tagged release, 0.5.0.

## [Unreleased]

### Added

- A `--goal` (or `goal:`) that narrows a lot to commits already merged skips the mockup unless the goal changes the layout, and the reviews judge the diff of the goal (L621, issue #40, [docs/orchestrate-gate.md](docs/orchestrate-gate.md#a-goal-that-narrows-a-lot-to-commits-already-merged-l621)): a lot with a goal and at least one work commit already in the base branch is launched without a spec step or mockup (journal `maquette sautée : l'objectif rétrécit le lot à N commit(s) déjà intégré(s) …`), unless the goal contains a layout word (`mise en page`, `layout`, `disposition`, `maquette`, `ecran`, `affichage`, `colonne`, `grille`, `responsive`), the lot has a sealed acceptation (a `spec: true` lot without a screen keeps its spec session). Its code-review brief names the commits after the launch head and the goal, and asks to mark `inchange: true` a major outside the goal; that mark now counts from review 1 for such a lot (`[suite code]` proposal, compliant verdict, no correction pass), a blocking finding still buys a pass. The narrowing is read from git at each review, no new state field to decide it. Measured on 05-11: 74 min and 1.28 M for a commit of four fixes.
- `cadence orchestrate`: a visible lot with no `screen:` (above 0.1 day, no `spec: true`) no longer plays the light mockup (L633, issue #43, [docs/orchestrate-spec.md](docs/orchestrate-spec.md#the-visible-fix-l633-issue-43)): `implement` (given the URL and start command of `orchestrate.ux`; a capture it cannot take goes under `nonVerifie`) captures the screen before and after the change at 1440 and 390 px, and the UX review reads the diff only, at the ordinary budget. The light mockup (and the forced states) stay for `screen: component` or `journey`, a new screen or a changed layout. Measured case: 33 min and 5.75 $ for 11 lines of SCSS.

## [1.56.0] - 2026-11-06

### Added

- The sealed-tests pre-check (L500) also lists the sealed tests of another lot that **import** a code file the lot's text cites (L628, [docs/orchestrate-gate.md](docs/orchestrate-gate.md)), `light` and `small` lots included: the lot of 05-11 that changed a delivered behaviour cited `src/…`, not the test that froze it, and was handed back at the commit for the lock. The brief names the code file (`it imports src/x.ts`) and tells the session to stop with the reseal gesture for the lead (`cadence spec reseal … --porteur <lot>`) under `questions`; the table line says it too.
- File bounds reach the writer (L626, [docs/config.md](docs/config.md#file-bounds-bounds)): the `bounds` key of `cadence.yaml` gives a file its limits (`lines`, `columns`, `chars`) and the tests that read it; the implementation and fix briefs list every bound with a limit (the file a lot touches is rarely the one its text cites), the new `cadence claude-hook bornes` (PostToolUse on Write, Edit and MultiEdit, in `hooks/hooks.json` and in the `--settings` of the implementation and fix sessions of a wave, where plugins are disabled) answers the measured line and the limit right after a write, and the targeted gate plays the declared tests with the files of the lot, before the full suite. cadence's own repository gets a `CLAUDE.md` with its bounds (README 64 lines and 160 columns, `docs/concepts.md` 15 Ko, CHANGELOG under `[Unreleased]`, new docs pages in `files`, checked by `test/docs-publiees-l626.test.ts`).
- A gate played on the remote host (`orchestrate.gate.host`) gives back the lot's session slot (L624, [docs/remote-gate.md](docs/remote-gate.md)): the pool no longer counts a lot whose gate runs on the host, so three gates there no longer leave the wave with 0 session (05-11, wave 1810-cad: 30 minutes empty, 16-minute gates on mini-blue, L622 waiting). The host has its own bound, `orchestrate.gate.maxParallel` (positive integer, 2 by default): the next gate waits, the journal says so, and the waiting lot holds no slot either (`gate.waiting` in its state, `porte en attente de l'hôte (3 min)` in `--status`). A gate played locally keeps its slot. The baseline of a red gate reuses the host slot its lot's gate holds (no deadlock with `maxParallel: 1`), and a lost connection, or a baseline that falls back to the local machine, removes `gate.remote` for the local command, so the lot takes its pool slot back.
- cadence's own `cadence.yaml` now plays its gate on the WSL of mini-blue (L618, `orchestrate.gate`: `host: mini-blue-wsl`, `install: npm ci`, `refs: [main, origin/main]`, [docs/remote-gate.md](docs/remote-gate.md)); without the alias in `~/.ssh/config` (a clone) the gate falls back to local, said. The measure on three real lots is left to the lead at the next wave ([docs/mesures/porte-deportee-mini-blue-2026-11-05.md](docs/mesures/porte-deportee-mini-blue-2026-11-05.md)).
- [docs/config.md](docs/config.md) (L602): one page lists the four folders cadence writes to (`.cadence/`, `.cadence/runs/<wave>/`, `~/.cadence/orchestrate`, `~/.local/share/cadence`) with what each holds, whether it is versioned and the variable that moves it (`CADENCE_HOME` does not move `~/.local/share/cadence`), and one table of the ten gates says where each is declared (the plan or `cadence.yaml`) and what it refuses. Linked from the README, `docs/overview.md` and `docs/fonctionnement.md`.
- `orchestrate.gate.refs` (L617, [docs/remote-gate.md](docs/remote-gate.md)): the references listed there (`main`, `origin/main`) are pushed to the host with the sha, so a build that runs `git merge-base HEAD main` or a test that reads `origin/main` finds them in the host's worktree instead of going red on « référence introuvable »; a reference missing locally falls back to the local gate, said. The same page now describes a host behind WSL (ssh server of the WSL, mirrored network, alias in `~/.ssh/config`), the idle stop of the WSL VM that makes the gate fall back to local, and the scheduled task of the Windows host that keeps it up.
- An out-of-rule expectation of the edge-case probe never buys a pass, and the wave table shows the minutes after the first review (L625, issue #41, [docs/orchestrate-cycle.md](docs/orchestrate-cycle.md#reviews-converge-follow-ups-and-a-wall-cap-l622)): the code review brief lists the probe's `[hors règle]` expectations and asks not to report them at all, and a major or minor that repeats one word for word is not counted (warning `<majeur|mineur> qui reprend une attente hors règle de la sonde, non compté`: no correction pass, no minors pass); a blocking finding still counts, and when that makes the review conforming its verdict is replaced by a `conforme, … attente hors règle …` note (the agent's « non conforme » would be read as non conforming by `raf done` and the delivery audit). The probe's warning now reads `attente hors règle du lot, non commitée (sous-tâche proposée au lead, hors des constats de revue)` instead of inviting to take it up as a review finding. The table gets an `après revue` column: the minutes of the steps after the lot's first code review (`—` before it).
- Code reviews converge (L622, issue #41, [docs/orchestrate-cycle.md](docs/orchestrate-cycle.md#reviews-converge-follow-ups-and-a-wall-cap-l622)): from the second code review, a major on a point the previous review had not raised, outside the goal of the lot and the lines it changes (`inchange: true`), no longer counts for non-conformity: it goes to the lot's proposals as `[suite code] <file>:<line> — <text>` and buys no correction pass, while a blocking finding (data loss, security, red tests) always buys one. The brief of that review lists the findings of the previous review and the follow-ups already set aside; a marked major that repeats a finding of the previous review counts, with a warning; a compliant review whose agent verdict still says « non conforme » gets the follow-up note as its verdict, so `raf done` reads it compliant. A lot whose wall passes twice the duration expected for its estimate is handed back with its findings instead of a new pass (`plafond de mur : N min sur M`); the wall counts the lot's steps only (an interrupted step counts for 0) and restarts when the lead resumes the lot with `--add`. The measure, first-time compliance and passes per lot before and after, is in [docs/mesures/revues-convergent-2026-11-05.md](docs/mesures/revues-convergent-2026-11-05.md).
- A lot whose goal could not be verified no longer comes out « prêt » in silence (L632, issue #42, [docs/orchestrate-cycle.md](docs/orchestrate-cycle.md)): with `orchestrate.prodAccess` false, launch and `--dry-run` alert when the title or the goal names `kubectl`, `port-forward`, `KUBECONFIG`, a cluster or a bench URL (the sessions start without cluster access, with the gesture to make); the table row, the journal (`--follow`) and the `raf review` note carry `objectif non vérifié : <first line>` when the report says `tests.vert` false with a command the gate does not play, or when the last review's `nonVerifie` names the goal; every brief says in one line that the session has no cluster access and that a goal which needs one is a question to the lead.
