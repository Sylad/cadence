### Fixed

- `cadence run` no longer leaves processes alive after it ends (L837, [docs/v2/2026-11-09-cadence-run.md](docs/v2/2026-11-09-cadence-run.md#déroulé)): everything the run starts (session, gate, servers sent to the background with `setsid`, `nohup` or the Bash tool) carries `CADENCE_RUN_PROCESSUS=<run id>`; at every end (integrated, handed back, failure, question, quota) these processes get SIGTERM, 3 s of grace, then SIGKILL, and the end says which were stopped and which still live. The run itself, its ancestors and the processes of another run are never touched. A `--fond` run killed by a signal is cleaned by its watcher; `--reponse` on an interrupted run and `--clore` clean it too.
