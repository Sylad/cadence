### Fixed

- A `cadence run` session no longer waits forever on a background command (L763, issue #63, [docs/v2/2026-11-09-cadence-run.md](docs/v2/2026-11-09-cadence-run.md)): a `claude -p` session is never woken by the end of a command started with `run_in_background` (two runs stuck 21 and 55 min on 17-11). Each session of the run now gets a `PreToolUse` hook (`v2/hooks/premier-plan.mjs`) that refuses `Bash` with `run_in_background` and says to run it in the foreground with a timeout matching its duration, gate included; its settings raise `BASH_MAX_TIMEOUT_MS` to 30 min, the time allowed to one gate command. The read hook of the full mode stays.

### Added

- `cadence run --liste [--inactif <minutes>]` flags a live session with no running command and nothing written to its transcript for N minutes (15 by default) as `session bloquée ?`, with the command to resume it: `kill <claude pid>`, then `cadence run --reponse <id> "reprends"` (L763, issue #63).
